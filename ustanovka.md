## 1. Терминал

Терминал — окно, в котором команды компьютеру отдают текстом. Почти вся настройка делается в нём.

Как открыть:

- **Windows:** нажми `Win`, набери `PowerShell`, нажми Enter. Ещё удобнее — открыть нужную папку в Проводнике, кликнуть правой кнопкой по пустому месту и выбрать «Открыть в Терминале».
- **macOS:** `Cmd+Пробел`, набери `Terminal`.
- **Linux:** `Ctrl+Alt+T`.

Терминал всегда «находится» в какой-то папке — она называется текущей. Команды выполняются относительно неё.

| Действие | Windows (PowerShell) | macOS / Linux |
|----------|----------------------|----------------|
| Где я сейчас | `pwd` | `pwd` |
| Что в папке | `ls` | `ls` |
| Перейти в папку | `cd analyst` | `cd analyst` |
| Подняться на уровень вверх | `cd ..` | `cd ..` |
| Перейти на другой диск | `cd D:\projects` | — |
| Создать папку | `mkdir analyst` | `mkdir analyst` |
| Очистить экран | `cls` | `clear` |

Полезные приёмы:

- `Tab` дописывает имя файла или папки за тебя.
- Стрелка вверх возвращает предыдущую команду.
- `Ctrl+C` останавливает выполняющуюся программу (например, Jupyter).
- Если в пути есть пробелы, бери его в кавычки: `cd "D:\Мои проекты"`. Лучше вообще не использовать пробелы и русские буквы в названиях папок с кодом.

## 2. Установка Python

### Windows

1. Открой python.org → Downloads и скачай установщик свежей версии (3.11 или новее).
2. Запусти его и **обязательно поставь галочку `Add python.exe to PATH`** на первом экране. Без неё терминал не найдёт Python.
3. Нажми Install Now.
4. **Закрой и заново открой терминал**, затем проверь:

```bash
python --version
```

```bash
pip --version
```

Обе команды должны вывести номер версии.

### macOS

Самый простой путь — установщик с python.org. На macOS команды называются `python3` и `pip3`:

```bash
python3 --version
```

### Linux

Python обычно уже установлен. На Ubuntu и Debian нужно доустановить модуль окружений:

```bash
sudo apt install python3-venv python3-pip
```

> Дальше в главе написано `python`. Если у тебя macOS или Linux, вне виртуального окружения пиши `python3`. Внутри активированного окружения `python` работает везде одинаково.

## 3. pip: установка библиотек

`pip` — программа, которая скачивает и устанавливает библиотеки Python из общего каталога PyPI.

| Команда | Что делает |
|---------|-----------|
| `pip install pandas` | Установить библиотеку |
| `pip install pandas matplotlib seaborn` | Установить несколько сразу |
| `pip install pandas==2.2.3` | Установить конкретную версию |
| `pip install --upgrade pandas` | Обновить |
| `pip uninstall pandas` | Удалить |
| `pip list` | Показать всё установленное |
| `pip show pandas` | Версия и расположение библиотеки |
| `pip freeze > requirements.txt` | Сохранить список библиотек в файл |
| `pip install -r requirements.txt` | Установить всё из файла |

Надёжный вариант записи — `python -m pip install pandas`. Он гарантирует, что библиотека поставится именно в тот Python, который сейчас запускается командой `python`.

Важно: **не устанавливай библиотеки, пока не активировал виртуальное окружение** — об этом следующий раздел.

## 4. Виртуальное окружение (venv)

### Что это и зачем

Виртуальное окружение — это отдельная папка с собственной копией Python и собственным набором библиотек. У каждого проекта оно своё.

Представь, что у тебя два проекта. Первому нужен pandas версии 1.5, второй написан под pandas 2.2. Если ставить библиотеки «в систему», они будут общими, и одновременно обе версии существовать не смогут: починишь один проект — сломаешь другой.

Окружение решает три задачи:

- **Изоляция.** Библиотеки одного проекта не мешают другому.
- **Воспроизводимость.** Список библиотек проекта можно сохранить в файл, и любой человек развернёт у себя точно такой же набор.
- **Чистота.** Надоел проект — удалил папку, и в системе не осталось мусора.

Правило: **один проект — одна папка — одно окружение.**

### Создание

Перейди в папку проекта и выполни:

```bash
python -m venv .venv
```

Разбор команды:

- `python -m venv` — запустить встроенный модуль `venv`;
- `.venv` — имя папки, в которой будет окружение. Называть можно как угодно, но `.venv` — общепринятый вариант: его узнают VS Code и другие программы.

В проекте появится папка `.venv`. Внутри лежат копия интерпретатора и место для библиотек. Руками там ничего менять не нужно.

### Активация

Создать окружение мало — его нужно **включать в каждом новом окне терминала**.

Windows, PowerShell:

```bash
.venv\Scripts\Activate.ps1
```

Windows, старая командная строка (cmd):

```bash
.venv\Scripts\activate.bat
```

macOS и Linux:

```bash
source .venv/bin/activate
```

Признак успеха — в начале строки терминала появилась приставка `(.venv)`:

```
(.venv) PS D:\analyst>
```

С этого момента `python` и `pip` в этом окне терминала относятся к окружению.

### Ошибка активации в PowerShell

На Windows при первой активации часто появляется красный текст «выполнение сценариев отключено в этой системе». Это настройка безопасности PowerShell. Разреши запуск локальных скриптов для своего пользователя (делается один раз):

```bash
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Ответь `Y` и повтори активацию.

### Как проверить, что окружение активно

Windows:

```bash
where.exe python
```

macOS и Linux:

```bash
which python
```

Первым в ответе должен идти путь внутри твоей папки `.venv`. Если там системный путь — окружение не активировано.

### Установка библиотек в окружение

Активируй окружение и ставь как обычно:

```bash
pip install numpy pandas matplotlib seaborn scipy statsmodels scikit-learn requests beautifulsoup4 jupyterlab
```

Это полный набор для книги. Всё установится внутрь `.venv`.

### Выход, удаление, пересоздание

Выйти из окружения:

```bash
deactivate
```

Удалить окружение — просто удалить папку `.venv`. Твой код при этом не пострадает: он лежит рядом, а не внутри.

Если окружение сломалось (так бывает), его не чинят, а пересоздают: удаляют папку, создают заново и ставят библиотеки из `requirements.txt`. Это занимает пару минут.

### Чего нельзя делать с окружением

- **Не клади свои файлы внутрь `.venv`.** Эта папка служебная.
- **Не отправляй `.venv` на GitHub.** Она большая и работает только на твоём компьютере. Добавь её в `.gitignore` (раздел 8).
- **Не переноси и не переименовывай папку проекта вместе с `.venv`.** Внутри окружения записаны абсолютные пути; после переезда оно перестанет работать. Перенёс проект — пересоздай окружение.
- **Не копируй `.venv` другу.** Передают `requirements.txt`, а окружение каждый создаёт у себя сам.

### Другие инструменты

Ты встретишь упоминания других менеджеров окружений. Все они решают ту же задачу:

| Инструмент | Что это |
|------------|---------|
| **venv** | Встроен в Python. Достаточен для всей книги — используем его |
| **conda** (Anaconda, Miniconda) | Отдельный менеджер, умеет ставить и разные версии самого Python. Популярен в науке о данных |
| **uv**, **Poetry** | Современные инструменты для управления проектом и зависимостями |

Не распыляйся: начни с `venv`. Принцип у всех одинаковый, и перейти на другой инструмент потом будет легко.

## 5. requirements.txt: список библиотек проекта

Это текстовый файл, в котором перечислены библиотеки проекта. По нему проект разворачивается на любом компьютере.

Сохранить текущее состояние окружения:

```bash
pip freeze > requirements.txt
```

В файле появятся строки с точными версиями:

```
numpy==2.1.3
pandas==2.2.3
matplotlib==3.9.2
```

Развернуть окружение по файлу (на другом компьютере или после пересоздания):

```bash
pip install -r requirements.txt
```

`pip freeze` записывает вообще всё, включая десятки вспомогательных библиотек. Для учебных проектов допустимо написать файл руками и перечислить только то, что ты сам импортируешь:

```
pandas
matplotlib
seaborn
scipy
jupyterlab
```

Обновляй `requirements.txt` каждый раз, когда ставишь в проект новую библиотеку.

## 6. Jupyter

### Запуск

Jupyter запускают **из активированного окружения и из папки проекта**:

```bash
jupyter lab
```

В браузере откроется вкладка с файлами проекта. Терминал при этом занят — в нём работает сервер Jupyter, закрывать его нельзя. Чтобы остановить, нажми в терминале `Ctrl+C`.

Раз Jupyter установлен в окружение и запущен из него, ноутбуки видят все библиотеки этого окружения. Это самый простой и надёжный способ.

### Проверка, что ноутбук использует нужное окружение

Выполни в ячейке:

```python
import sys
print(sys.executable)
```

Путь должен вести в папку `.venv` твоего проекта.

### Установка библиотеки из ноутбука

Если во время работы не хватило библиотеки, её можно поставить прямо из ячейки:

```
%pip install plotly
```

Команда `%pip` ставит библиотеку именно в то окружение, в котором работает ноутбук. После установки перезапусти ядро: меню Kernel → Restart Kernel.

### Ядро (kernel)

Ядро — это процесс Python, который выполняет ячейки ноутбука. Что о нём нужно знать:

- переменные живут, пока живо ядро; после перезапуска все ячейки нужно выполнить заново;
- ячейки выполняются в том порядке, в каком ты их запускал, а не сверху вниз. Число в квадратных скобках слева от ячейки показывает порядок;
- если ноутбук ведёт себя странно — Kernel → Restart Kernel and Run All Cells. Это же обязательная проверка перед публикацией.

## 7. VS Code

Visual Studio Code — бесплатный редактор кода. В нём удобно держать всё сразу: файлы проекта, ноутбуки, терминал и Git.

Настройка:

1. Установи VS Code с code.visualstudio.com.
2. Открой **папку проекта**: File → Open Folder. Именно папку, а не отдельный файл.
3. Во вкладке Extensions (значок с квадратами слева) установи расширения **Python** и **Jupyter** от Microsoft.
4. Выбери интерпретатор: `Ctrl+Shift+P` → набери `Python: Select Interpreter` → выбери вариант с `.venv`.
5. Открой встроенный терминал: `` Ctrl+` ``. После выбора интерпретатора VS Code будет сам активировать окружение в новых терминалах.

Файлы `.ipynb` открываются прямо в VS Code. В правом верхнем углу ноутбука есть кнопка выбора ядра — там тоже нужно указать `.venv`.

## 8. Git и GitHub

### Установка и первая настройка

1. Скачай Git с git-scm.com и установи с настройками по умолчанию.
2. Представься (один раз на компьютере) — эти данные попадут в историю изменений:

```bash
git config --global user.name "Твоё Имя"
```

```bash
git config --global user.email "твоя_почта@example.com"
```

Почту укажи ту же, что в аккаунте GitHub.

### Файл .gitignore

До первого коммита создай в корне проекта файл `.gitignore`. В нём перечислено то, что Git не должен отслеживать:

```
# виртуальное окружение
.venv/

# секреты
.env

# служебные файлы Python и Jupyter
__pycache__/
.ipynb_checkpoints/

# большие и сырые данные
data/raw/

# служебные файлы систем и редакторов
.DS_Store
.vscode/
```

### Основные команды

| Команда | Что делает |
|---------|-----------|
| `git init` | Сделать папку репозиторием |
| `git status` | Что изменилось. Запускай постоянно |
| `git add .` | Подготовить все изменения к сохранению |
| `git commit -m "сообщение"` | Сохранить снимок изменений в историю |
| `git push` | Отправить на GitHub |
| `git pull` | Забрать изменения с GitHub |
| `git log --oneline` | Короткая история коммитов |
| `git clone адрес` | Скачать чужой репозиторий |

### Первая отправка на GitHub

1. На github.com нажми New repository, задай имя, **не ставь** галочки про README и .gitignore (они у тебя уже есть), нажми Create.
2. В папке проекта выполни по очереди:

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "Первый коммит: структура проекта"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/ТВОЙ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
```

```bash
git push -u origin main
```

При первой отправке откроется окно браузера для входа в GitHub — это нормально.

Дальше рабочий цикл состоит из трёх команд: `git add .`, затем `git commit -m "что сделал"`, затем `git push`.

Пиши сообщения коммитов по делу: «Добавил когортный анализ», а не «изменения» или «asdf».

## 9. Новый проект с нуля: пошагово

Полная последовательность. Сохрани её — будешь повторять для каждого проекта.

**Шаг 1.** Создай папку и перейди в неё:

```bash
mkdir sales-analysis
```

```bash
cd sales-analysis
```

**Шаг 2.** Создай окружение:

```bash
python -m venv .venv
```

**Шаг 3.** Активируй его (вариант для Windows; для других систем — раздел 4):

```bash
.venv\Scripts\Activate.ps1
```

**Шаг 4.** Обнови pip и установи библиотеки:

```bash
python -m pip install --upgrade pip
```

```bash
pip install pandas matplotlib seaborn scipy jupyterlab
```

**Шаг 5.** Сохрани список библиотек:

```bash
pip freeze > requirements.txt
```

**Шаг 6.** Создай структуру папок:

```bash
mkdir data, notebooks, images
```

На macOS и Linux — `mkdir data notebooks images`, без запятых.

**Шаг 7.** Создай файлы `.gitignore` (содержимое — в разделе 8) и `README.md` (шаблон — в разделе 12.6 книги).

**Шаг 8.** Инициализируй Git и сделай первый коммит (раздел 8).

**Шаг 9.** Запусти Jupyter и создай ноутбук в папке `notebooks`:

```bash
jupyter lab
```

В итоге проект выглядит так:

```
sales-analysis/
├── .venv/               — окружение (не попадает в Git)
├── data/                — данные
├── notebooks/
│   └── analysis.ipynb   — анализ
├── images/              — графики для README
├── .gitignore
├── README.md
└── requirements.txt
```

### Пути к файлам в ноутбуке

Ноутбук лежит в `notebooks`, данные — в `data`. Относительный путь считается от папки, где лежит сам ноутбук, поэтому нужно подняться на уровень вверх:

```python
df = pd.read_csv("../data/orders.csv")
```

Не пиши абсолютные пути вида `C:\Users\Ivan\...` — на другом компьютере такой код не запустится.

### Каждый следующий день

Когда проект уже создан, начало работы — три действия:

1. Открыть терминал в папке проекта.
2. Активировать окружение.
3. Запустить `jupyter lab` (или открыть папку в VS Code).

## 10. Как запустить чужой проект с GitHub

Так ты будешь работать со всеми репозиториями из книги.

**Шаг 1.** Скопируй адрес: на странице репозитория кнопка Code → HTTPS.

**Шаг 2.** Склонируй и перейди в папку:

```

cd pandas_exercises
```

**Шаг 3.** Создай и активируй окружение — своё для этого репозитория:

```

```

```bash

```

Замечания:

- Старые репозитории могут быть написаны под старые версии библиотек, и часть кода выдаст ошибки или предупреждения. Чаще всего достаточно прочитать сообщение: в нём обычно сказано, чем заменить устаревшую функцию.
- Чтобы сохранять собственные решения у себя на GitHub, сделай **fork** — кнопка Fork на странице репозитория создаст твою копию. Клонируй уже её.
- Если нужен один файл, а не весь репозиторий, открой его на GitHub и нажми кнопку скачивания.

## 11. Файл .env и секреты

Не путай: `.venv` — это **папка** с окружением Python. `.env` — это **текстовый файл** с настройками и секретами проекта. Названия похожи, задачи разные.

### Зачем нужен

Пароли от баз данных и ключи API нельзя писать прямо в коде: код попадает на GitHub, и секрет увидят все. Украденные ключи находят автоматические сканеры за считаные минуты.

Решение — хранить секреты в переменных окружения, а в коде только читать их.

### Как пользоваться

Установи библиотеку:

```bash
pip install python-dotenv
```

Создай в корне проекта файл `.env`:

```
DB_HOST=localhost
DB_USER=analyst
DB_PASSWORD=очень_секретный_пароль
API_KEY=abc123
```

Правила записи: одна переменная на строку, без пробелов вокруг `=`, без кавычек.

Прочитай значения в коде:

```python
import os
from dotenv import load_dotenv

load_dotenv()                          # загрузить переменные из файла .env

password = os.getenv("DB_PASSWORD")
api_key = os.getenv("API_KEY")
```

Если ноутбук лежит в подпапке, `load_dotenv()` сам поищет файл в родительских папках.

### Обязательные правила

1. **Добавь `.env` в `.gitignore` до первого коммита.**
2. Положи в репозиторий файл `.env.example` — такой же, но без настоящих значений. По нему другой человек поймёт, какие переменные нужны:

```
DB_HOST=
DB_USER=
DB_PASSWORD=
API_KEY=
```

3. Если секрет всё-таки попал на GitHub — недостаточно удалить его следующим коммитом: он останется в истории. Ключ нужно немедленно отозвать и выпустить новый.

## 12. Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `python` не является командой | Python не добавлен в PATH. Переустанови с галочкой `Add python.exe to PATH` и открой терминал заново |
| Команда `python` открывает Microsoft Store | То же самое: поставь Python с python.org |
| «Выполнение сценариев отключено» при активации | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (раздел 4) |
| `ModuleNotFoundError: No module named 'pandas'` | Библиотека не установлена **в это** окружение. Проверь, что окружение активно, и выполни `pip install pandas` |
| Установил библиотеку, а ноутбук её не видит | Ноутбук запущен на другом ядре. Проверь `sys.executable` (раздел 6), выбери ядро `.venv`, перезапусти ядро |
| `pip` ставит не туда | Используй `python -m pip install ...` при активном окружении |
| `jupyter` не является командой | Jupyter не установлен в это окружение или оно не активировано |
| `FileNotFoundError` при чтении файла | Неверный путь. Посмотри текущую папку: `import os; print(os.getcwd())` |
| Кракозябры вместо русских букв | Добавь `encoding="utf-8"` или `encoding="cp1251"` |
| После переноса папки проекта окружение не работает | Удали `.venv` и создай заново |
| `git push` отклонён | На GitHub есть изменения, которых нет у тебя. Сначала `git pull` |
| В Git попала папка `.venv` | Добавь её в `.gitignore`, затем `git rm -r --cached .venv` и сделай коммит |

Если ничего не помогло: скопируй **последнюю строку** сообщения об ошибке и вбей её в поиск. Почти наверняка с этим уже сталкивались.

## 13. Шпаргалка команд

```
# ── Окружение ───────────────────────────────────────────
python -m venv .venv                    создать
.venv\Scripts\Activate.ps1              активировать (Windows PowerShell)
source .venv/bin/activate               активировать (macOS, Linux)
deactivate                              выйти

# ── Библиотеки ──────────────────────────────────────────
pip install имя                         установить
pip install -r requirements.txt         установить всё из файла
pip freeze > requirements.txt           сохранить список
pip list                                показать установленное

# ── Jupyter ─────────────────────────────────────────────
jupyter lab                             запустить
Ctrl+C                                  остановить

# ── Git ─────────────────────────────────────────────────
git status                              что изменилось
git add .                               подготовить изменения
git commit -m "сообщение"               сохранить
git push                                отправить на GitHub
git pull                                забрать с GitHub
git clone адрес                         скачать репозиторий
```
