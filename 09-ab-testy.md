# Глава 9. Гипотезы и A/B-тесты

Ты увидел в данных разницу: конверсия в группе B — 5,6 %, в группе A — 5,0 %. Это настоящий эффект или случайность? На этот вопрос отвечает проверка гипотез. A/B-тест — её главное применение в бизнесе и обязательная тема собеседований.

## 9.1. Выборка и генеральная совокупность

- **Генеральная совокупность** — все, о ком мы хотим сделать вывод (все пользователи сайта, включая будущих).
- **Выборка** — те, кого мы наблюдали на самом деле.

Мы почти всегда видим только выборку, а выводы хотим сделать обо всех. Проблема в том, что выборки случайны: возьми другую тысячу пользователей — получишь немного другое среднее.

Посмотрим на эту случайность:

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(42)

population = rng.gamma(2.0, 1500, 100_000)       # «все» заказы, среднее около 3000
print(round(population.mean()))

sample_means = [rng.choice(population, 200).mean() for _ in range(2000)]
print(round(np.mean(sample_means)), round(np.std(sample_means)))
```

<!-- result -->
*Результат:*

```output
3002
3001 156
```
<!-- /result -->



Средние двух тысяч выборок по 200 заказов разбросаны вокруг истинного значения с отклонением около 150 рублей. Этот разброс называют **стандартной ошибкой**. Она уменьшается с ростом выборки пропорционально корню из её размера: чтобы стать вдвое точнее, нужно вчетверо больше данных.

**Центральная предельная теорема** говорит: распределение выборочных средних близко к нормальному, даже если сами данные сильно скошены — лишь бы выборка была достаточно большой. Благодаря ей работает большинство статистических тестов.

## 9.2. Доверительный интервал

Вместо одного числа («средний чек — 2900») честнее назвать диапазон: «средний чек — от 2600 до 3200 с уверенностью 95 %».

```python
sample = rng.choice(population, 200)

mean = sample.mean()
se = sample.std(ddof=1) / np.sqrt(len(sample))      # стандартная ошибка
low, high = mean - 1.96 * se, mean + 1.96 * se
print(round(mean), round(low), round(high))
```

<!-- result -->
*Результат:*

```output
2896 2597 3194
```
<!-- /result -->



Число 1,96 — граница, внутри которой лежит 95 % нормального распределения.

Как понимать: если повторить процедуру много раз, примерно в 95 % случаев построенный интервал накроет истинное значение. Чем шире интервал, тем меньше мы знаем.

### Бутстрап: интервал для чего угодно

Для медианы или перцентиля простой формулы нет. Бутстрап решает задачу перебором: много раз берём из выборки новую выборку **с возвращением** и считаем метрику.

```python
boot = [np.median(rng.choice(sample, len(sample), replace=True)) for _ in range(5000)]
print(np.percentile(boot, [2.5, 97.5]).round())
```

<!-- result -->
*Результат:*

```output
[1978. 2558.]
```
<!-- /result -->



Метод универсален и интуитивен — его стоит уметь объяснить на собеседовании.

## 9.3. Логика проверки гипотез

Проверка гипотез похожа на суд с презумпцией невиновности.

1. **Нулевая гипотеза (H₀)** — «эффекта нет», различие случайно.
2. **Альтернативная гипотеза (H₁)** — «эффект есть».
3. Считаем **p-value** — вероятность получить такое же или ещё более сильное различие, **если H₀ верна**.
4. Если p-value меньше заранее выбранного порога **α** (обычно 0,05) — отвергаем H₀: результат **статистически значим**.

Смысл: если бы эффекта не было, такие данные были бы большой редкостью. Значит, эффект, скорее всего, есть.

### Чем p-value НЕ является

Самый популярный вопрос на собеседованиях.

- Это **не** вероятность того, что H₀ верна.
- Это **не** вероятность того, что результат случаен.
- Это **не** размер эффекта. Маленькое p-value говорит «эффект, вероятно, есть», а не «эффект большой».
- `p > 0,05` **не** доказывает, что эффекта нет. Возможно, просто не хватило данных.

### Два вида ошибок

| | H₀ на самом деле верна | H₀ на самом деле неверна |
|---|---|---|
| **Отвергли H₀** | Ошибка I рода (ложная тревога), вероятность α | Верно. Вероятность — **мощность** |
| **Не отвергли H₀** | Верно | Ошибка II рода (пропустили эффект), вероятность β |

- **α** (уровень значимости) — как часто мы согласны видеть эффект там, где его нет. Стандарт — 5 %.
- **Мощность** (1 − β) — вероятность заметить эффект, если он есть. Стандарт — 80 %.

## 9.4. Основные тесты

| Что сравниваем | Тест | Функция в SciPy |
|----------------|------|-----------------|
| Средние двух групп | t-тест Уэлча | `stats.ttest_ind(a, b, equal_var=False)` |
| Распределения двух групп, данные скошены или с выбросами | Манна — Уитни | `stats.mannwhitneyu(a, b)` |
| Доли (конверсии) двух групп | z-тест пропорций или хи-квадрат | `stats.chi2_contingency(table)` |
| Средние «до и после» у одних и тех же объектов | Парный t-тест | `stats.ttest_rel(before, after)` |
| Средние трёх и более групп | ANOVA | `stats.f_oneway(a, b, c)` |
| Связь двух категориальных признаков | Хи-квадрат | `stats.chi2_contingency(table)` |

### Сравнение средних

```python
group_a = rng.gamma(2.0, 1500, 1000)      # средний чек около 3000
group_b = rng.gamma(2.0, 1600, 1000)      # около 3200

t_stat, p_value = stats.ttest_ind(group_a, group_b, equal_var=False)
print(round(group_a.mean()), round(group_b.mean()), round(p_value, 4))

u_stat, p_mw = stats.mannwhitneyu(group_a, group_b)
print(round(p_mw, 4))
```

0.0005

Всегда ставь `equal_var=False` — это тест Уэлча, он не требует равенства дисперсий в группах.

### Сравнение конверсий

```python
visitors_a, orders_a = 10000, 500      # 5.0 %
visitors_b, orders_b = 10000, 560      # 5.6 %

table = [
    [orders_a, visitors_a - orders_a],
    [orders_b, visitors_b - orders_b],
]
chi2, p_value, dof, expected = stats.chi2_contingency(table, correction=False)
print(round(p_value, 4))
```

<!-- result -->
*Результат:*

```output
0.0583
```
<!-- /result -->



То же самое вручную, чтобы понять механику z-теста:

```python
p_a, p_b = orders_a / visitors_a, orders_b / visitors_b
p_pool = (orders_a + orders_b) / (visitors_a + visitors_b)
se = np.sqrt(p_pool * (1 - p_pool) * (1 / visitors_a + 1 / visitors_b))
z = (p_b - p_a) / se
p_value = 2 * (1 - stats.norm.cdf(abs(z)))
print(round(z, 2), round(p_value, 4))

# Доверительный интервал для разницы конверсий
se_diff = np.sqrt(p_a * (1 - p_a) / visitors_a + p_b * (1 - p_b) / visitors_b)
diff = p_b - p_a
print(round(diff - 1.96 * se_diff, 4), round(diff + 1.96 * se_diff, 4))
```

<!-- result -->
*Результат:*

```output
1.89 0.0583
-0.0002 0.0122
```
<!-- /result -->



Оба способа дают p-value около 0,058. Формально при α = 0,05 результат **не** значим, хотя разница в 0,6 процентного пункта выглядела убедительно. Доверительный интервал для разницы — примерно от −0,02 до +1,22 п. п. — включает ноль. Вывод честного аналитика: «данных недостаточно, чтобы утверждать, что B лучше».

Готовая функция для этого же расчёта есть в библиотеке statsmodels: `proportions_ztest`.

## 9.5. A/B-тест от начала до конца

A/B-тест — эксперимент: пользователей случайно делят на группы, одной показывают старую версию (A, контроль), другой — новую (B), и сравнивают метрику. Случайное разделение — единственный надёжный способ доказать причинность: группы отличаются только изменением.

### Шаг 1. Гипотеза и метрика

Формулировка: «Если сделаем X, то метрика Y вырастет, потому что Z».

- **Целевая метрика** — одна, по ней принимается решение (конверсия в покупку).
- **Контрольные метрики** — то, что не должно ухудшиться (средний чек, число возвратов).

### Шаг 2. Размер выборки — до запуска

Нужно заранее решить четыре вещи:

- базовое значение метрики (сейчас конверсия 5 %);
- **MDE** — минимальный эффект, который хотим заметить (хотим увидеть рост до 5,5 %);
- α = 0,05;
- мощность = 0,8.

```python
def sample_size(p1, p2, alpha=0.05, power=0.8):
    """Размер одной группы для сравнения двух долей."""
    z_alpha = stats.norm.ppf(1 - alpha / 2)
    z_beta = stats.norm.ppf(power)
    variance = p1 * (1 - p1) + p2 * (1 - p2)
    return int(np.ceil((z_alpha + z_beta) ** 2 * variance / (p1 - p2) ** 2))

print(sample_size(0.05, 0.055))    # около 31 000 на группу
print(sample_size(0.05, 0.06))     # около 8 200 на группу
```

<!-- result -->
*Результат:*

```output
31231
8155
```
<!-- /result -->



Главная закономерность: чтобы поймать вдвое меньший эффект, нужно примерно вчетверо больше пользователей. Отсюда и длительность теста: размер выборки делим на дневной трафик.

### Шаг 3. Запуск

- Пользователи делятся случайно, и каждый всегда видит одну и ту же версию.
- Тест идёт целое число недель: поведение в будни и выходные разное.
- Минимум — одна-две недели, даже если выборка набралась раньше.

### Шаг 4. Проверка корректности

- **A/A-тест** — обе группы видят одно и то же. Если тест находит «значимую» разницу, сломана система разделения.
- **SRM (Sample Ratio Mismatch)** — делили 50/50, а получили 10 000 и 10 600. Это признак технической ошибки; результатам такого теста верить нельзя.

```python
observed = [10000, 10600]
chi2, p = stats.chisquare(observed)
print(round(p, 6))      # очень маленькое p-value — с разделением что-то не так
```

<!-- result -->
*Результат:*

```output
2.9e-05
```
<!-- /result -->



### Шаг 5. Анализ и решение

Считаем тест, который выбрали заранее, и смотрим не только на p-value, но и на доверительный интервал эффекта. Затем проверяем контрольные метрики.

Итог оформляется так:

> Конверсия выросла с 5,0 % до 5,6 % (+12 % относительно). Доверительный интервал разницы: от −0,02 до +1,22 п. п., p = 0,058. Эффект статистически не подтверждён. Рекомендация: продлить тест до расчётного размера выборки.

## 9.6. Ошибки, которые ломают A/B-тесты

1. **Подглядывание (peeking).** Смотреть на p-value каждый день и остановить тест, как только оно упало ниже 0,05. При таком подходе вероятность ложной тревоги вырастает с 5 % до 20–30 %. Размер выборки фиксируется заранее.
2. **Множественные сравнения.** Проверил 20 метрик — в среднем одна будет «значимой» случайно. Лекарство — поправка Бонферрони (делим α на число сравнений) или одна заранее выбранная целевая метрика.
3. **Поиск сегмента после теста.** «В целом эффекта нет, но у женщин 25–30 лет из Казани на iOS — есть!» Это почти наверняка случайность.
4. **Эффект новизны.** Пользователи кликают на новое просто потому, что оно новое. Через пару недель эффект исчезает.
5. **Статистическая значимость ≠ практическая.** На миллионе пользователей значимым станет и рост на 0,01 %. Вопрос — окупит ли он затраты на внедрение.
6. **Средний чек и t-тест.** На метриках с тяжёлым хвостом один крупный клиент может решить исход. Проверяй выбросы, используй бутстрап или Манна — Уитни.

## 9.7. Байесовский подход: коротко

Классический (частотный) подход отвечает на вопрос «насколько удивительны данные, если эффекта нет». Байесовский отвечает на вопрос, который на самом деле задаёт бизнес: **«с какой вероятностью B лучше A?»**

```python
# Апостериорные распределения конверсий: Beta(1 + успехи, 1 + неудачи)
post_a = rng.beta(1 + orders_a, 1 + visitors_a - orders_a, 100_000)
post_b = rng.beta(1 + orders_b, 1 + visitors_b - orders_b, 100_000)

print(round((post_b > post_a).mean(), 3))                    # вероятность, что B лучше A
print(np.percentile(post_b - post_a, [2.5, 97.5]).round(4))  # интервал для разницы
```

<!-- result -->
*Результат:*

```output
0.971
[-0.0002  0.0122]
```
<!-- /result -->



Результат — около 0,97: «B лучше A с вероятностью 97 %». Такую фразу менеджеру понять гораздо проще, чем «p = 0,058». Данные при этом те же — отличается вопрос, на который мы отвечаем.

## Решения

### Задание 1. A/A-симуляция

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(42)

p_values = []
for _ in range(1000):
    a = rng.normal(100, 15, 500)
    b = rng.normal(100, 15, 500)              # то же самое распределение
    p_values.append(stats.ttest_ind(a, b, equal_var=False).pvalue)

p_values = np.array(p_values)
print((p_values < 0.05).mean())               # около 0.05
```

<!-- result -->
*Результат:*

```output
0.054
```
<!-- /result -->



Группы взяты из одного распределения, то есть нулевая гипотеза **верна**. Тем не менее примерно в 5 % случаев тест показывает «значимую» разницу. Это и есть ошибка I рода, и её вероятность равна α по построению. Вывод: при пороге 0,05 каждый двадцатый тест без всякого эффекта окажется «успешным».

Дополнительно построй гистограмму `p_values`: она будет ровной. При верной нулевой гипотезе p-value распределено равномерно от 0 до 1.

### Задание 2. Вред подглядывания

```python
rng = np.random.default_rng(42)

false_positives = 0
for _ in range(1000):
    a = rng.normal(100, 15, 2000)
    b = rng.normal(100, 15, 2000)
    for n in range(100, 2001, 100):           # смотрим после каждых 100 наблюдений
        if stats.ttest_ind(a[:n], b[:n], equal_var=False).pvalue < 0.05:
            false_positives += 1
            break                             # «нашли эффект» и остановили тест

print(false_positives / 1000)                 # около 0.25
```

<!-- result -->
*Результат:*

```output
0.254
```
<!-- /result -->



Эффекта по-прежнему нет, но тест «находит» его уже в каждом четвёртом случае вместо каждого двадцатого. Причина: мы даём случайности 20 попыток пересечь порог и останавливаемся на первой удачной.

Поэтому размер выборки фиксируют заранее и смотрят на результат один раз. Если подглядывать необходимо, используют специальные методы последовательного тестирования с более строгими порогами.

### Задание 3. Размер выборки и длительность

```python
def sample_size(p1, p2, alpha=0.05, power=0.8):
    z_alpha = stats.norm.ppf(1 - alpha / 2)
    z_beta = stats.norm.ppf(power)
    variance = p1 * (1 - p1) + p2 * (1 - p2)
    return int(np.ceil((z_alpha + z_beta) ** 2 * variance / (p1 - p2) ** 2))

n = sample_size(0.03, 0.033)
days = np.ceil(2 * n / 2000)

print(n)                                      # 53208 на группу
print(days, np.ceil(days / 7) * 7)            # 54 дня → округляем до 56 (8 недель)
```

Нужно около 53 тысяч пользователей в каждой группе, то есть примерно 106 тысяч всего. При 2000 посетителей в день это 54 дня; округляем вверх до целых недель — 8 недель.

### Задание 4. Анализ A/B-теста

```python
visitors_a, orders_a = 15000, 420
visitors_b, orders_b = 15100, 489

p_a, p_b = orders_a / visitors_a, orders_b / visitors_b

p_pool = (orders_a + orders_b) / (visitors_a + visitors_b)
se_pool = np.sqrt(p_pool * (1 - p_pool) * (1 / visitors_a + 1 / visitors_b))
z = (p_b - p_a) / se_pool
p_value = 2 * (1 - stats.norm.cdf(abs(z)))

se_diff = np.sqrt(p_a * (1 - p_a) / visitors_a + p_b * (1 - p_b) / visitors_b)
diff = p_b - p_a
low, high = diff - 1.96 * se_diff, diff + 1.96 * se_diff

print(f"A: {p_a:.2%}, B: {p_b:.2%}, относительный рост: {p_b / p_a - 1:.1%}")
print(f"z = {z:.2f}, p-value = {p_value:.3f}")
print(f"95 % ДИ разницы: от {low:.2%} до {high:.2%}")

# Проверка на SRM: размеры групп должны соответствовать разбиению 50/50
print("SRM p-value:", round(stats.chisquare([visitors_a, visitors_b]).pvalue, 3))
```

### Задание 5. Байесовский вариант

rng = np.random.default_rng(42)

post_a = rng.beta(1 + orders_a, 1 + visitors_a - orders_a, 200_000)
post_b = rng.beta(1 + orders_b, 1 + visitors_b - orders_b, 200_000)

print("P(B лучше A):", round((post_b > post_a).mean(), 3))                          # около 0.986
print("P(B лучше A более чем на 5 %):", round((post_b / post_a - 1 > 0.05).mean(), 3))   # около 0.93

### Задание 6. Бутстрап для медианы

```python
import pandas as pd

amount = pd.read_csv("orders_clean.csv")["amount"].to_numpy()
rng = np.random.default_rng(42)

medians = np.array([
    np.median(rng.choice(amount, size=len(amount), replace=True))
    for _ in range(5000)
])

low, high = np.percentile(medians, [2.5, 97.5])
print(f"Медиана: {np.median(amount):.0f}, 95 % ДИ: от {low:.0f} до {high:.0f}")
```
