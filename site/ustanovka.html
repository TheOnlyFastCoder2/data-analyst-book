1. Терминал

Терминал — окно, в котором команды компьютеру отдают текстом. Почти вся настройка делается в нём.

Как открыть:

  • нажми Cmd+Пробел, набери Terminal (или «Терминал»), нажми Enter;
  • либо открой Finder → Программы → Утилиты → Терминал.

Сразу закрепи его в Dock: правый клик по значку → Параметры → Оставить в Dock.

Чтобы открыть терминал сразу в нужной папке, перетащи папку из Finder на значок Терминала в Dock.

На macOS в терминале работает оболочка zsh. Приглашение выглядит примерно так:

ivan@MacBook-Air analyst %

Слева направо: имя пользователя, имя компьютера, текущая папка, знак %. В инструкциях в интернете ты встретишь знак $ в начале команд — это обозначение «вводить в терминале», сам знак набирать не нужно.

Терминал всегда «находится» в какой-то папке — она называется текущей. Команды выполняются относительно неё.

ДействиеКоманда
Где я сейчасpwd
Что в папкеls
Что в папке, включая скрытые файлыls -a
Перейти в папкуcd analyst
Подняться на уровень вверхcd ..
Перейти в домашнюю папкуcd ~
Создать папкуmkdir analyst
Создать пустой файлtouch notes.txt
Показать содержимое файлаcat notes.txt
Открыть текущую папку в Finderopen .
Очистить экранclear или Cmd+K

Домашняя папка обозначается знаком ~ — это /Users/твоё_имя. Проекты удобно держать в отдельной папке внутри неё, например ~/projects.

Полезные приёмы:

  • Tab дописывает имя файла или папки за тебя.
  • Стрелка вверх возвращает предыдущую команду.
  • Ctrl+C останавливает выполняющуюся программу (например, Jupyter). Именно Ctrl, а не Cmd: Cmd+C в терминале — обычное копирование.
  • Cmd+T открывает новую вкладку терминала.
  • Не используй пробелы и русские буквы в названиях папок с кодом: sales-analysis, а не Анализ продаж. Если пробел в пути всё же есть, бери имя в кавычки: cd ~/"Мои проекты".

Скрытые файлы

Файлы и папки, имя которых начинается с точки (.venv, .gitignore, .env), на macOS скрыты. Finder их не показывает, пока не нажмёшь Cmd+Shift+. (точка). В терминале их показывает ls -a.

Создавать такие файлы проще всего из терминала (touch .gitignore) или из VS Code.

2. Инструменты разработчика и Homebrew

Command Line Tools

Набор базовых инструментов от Apple, в который входит Git. Установи его первым делом:

bash
xcode-select --install

Появится окно — нажми «Установить» и дождись окончания. Если в ответ написано, что инструменты уже установлены, — всё в порядке.

Проверка:

bash
git --version

Homebrew

Homebrew — менеджер программ для macOS: устанавливает и обновляет программы одной командой. Он необязателен, но сильно упрощает жизнь.

Команду установки возьми на официальном сайте brew.sh — она там на главной странице. Скопируй её в терминал и выполни.

Важно: в конце установки Homebrew печатает раздел Next steps с двумя-тремя командами. Их нужно выполнить — они добавляют brew в настройки оболочки. Без этого терминал ответит command not found: brew.

Проверка (в новом окне терминала):

bash
brew --version

Основные команды:

КомандаЧто делает
brew install имяУстановить программу для терминала
brew install --cask имяУстановить обычное приложение с окном
brew upgradeОбновить всё установленное
brew listПоказать установленное

3. Установка Python

На macOS может быть предустановлен старый системный Python. Им пользоваться не нужно — ставим свежий.

Способ 1: через Homebrew (рекомендуется).

bash
brew install python

Способ 2: установщик. Скачай с python.org → Downloads файл macOS 64-bit universal2 installer и запусти его. Он подходит и для процессоров Apple (M1 и новее), и для Intel.

Проверка:

bash
python3 --version
bash
pip3 --version

python или python3

Главная особенность macOS: вне виртуального окружения команды называются python3 и pip3. Просто python выдаст ошибку command not found: python.

Внутри активированного виртуального окружения (раздел 5) работают и python, и pip — и указывают они на правильный Python.

Правило, которое избавит от путаницы:

  • python3 пишем один раз — когда создаём окружение;
  • дальше активируем окружение и везде пишем python и pip.

В остальных главах книги написано python — подразумевается, что окружение активировано.

Процессоры Apple и Intel

Узнать, какой у тебя процессор: значок яблока в левом верхнем углу экрана → «Об этом Mac». Для работы по книге разницы нет: все нужные библиотеки поддерживают оба варианта. Упоминание пригодится только при чтении старых инструкций в интернете, где для Apple Silicon предлагают обходные пути, — сейчас они не нужны.

4. pip: установка библиотек

pip — программа, которая скачивает и устанавливает библиотеки Python из общего каталога PyPI.

КомандаЧто делает
pip install pandasУстановить библиотеку
pip install pandas matplotlib seabornУстановить несколько сразу
pip install pandas==2.2.3Установить конкретную версию
pip install --upgrade pandasОбновить
pip uninstall pandasУдалить
pip listПоказать всё установленное
pip show pandasВерсия и расположение библиотеки
pip freeze > requirements.txtСохранить список библиотек в файл
pip install -r requirements.txtУстановить всё из файла

Надёжный вариант записи — python -m pip install pandas. Он гарантирует, что библиотека поставится именно в тот Python, который сейчас запускается командой python.

Важно: не устанавливай библиотеки, пока не активировал виртуальное окружение. Python из Homebrew вообще не даст этого сделать и ответит ошибкой externally-managed-environment. Это не поломка, а защита: система напоминает, что библиотеки нужно ставить в окружение.

5. Виртуальное окружение (venv)

Что это и зачем

Виртуальное окружение — это отдельная папка с собственной копией Python и собственным набором библиотек. У каждого проекта оно своё.

Представь, что у тебя два проекта. Первому нужен pandas версии 1.5, второй написан под pandas 2.2. Если ставить библиотеки «в систему», они будут общими, и одновременно обе версии существовать не смогут: починишь один проект — сломаешь другой.

Окружение решает три задачи:

  • Изоляция. Библиотеки одного проекта не мешают другому.
  • Воспроизводимость. Список библиотек проекта можно сохранить в файл, и любой человек развернёт у себя точно такой же набор.
  • Чистота. Надоел проект — удалил папку, и в системе не осталось мусора.

Правило: один проект — одна папка — одно окружение.

Создание

Перейди в папку проекта и выполни:

bash
python3 -m venv .venv

Разбор команды:

  • python3 -m venv — запустить встроенный модуль venv;
  • .venv — имя папки, в которой будет окружение. Называть можно как угодно, но .venv — общепринятый вариант: его узнают VS Code и другие программы.

В проекте появится папка .venv. Она скрытая: в Finder её не видно, в терминале её показывает ls -a. Внутри лежат копия интерпретатора и место для библиотек. Руками там ничего менять не нужно.

Активация

Создать окружение мало — его нужно включать в каждом новом окне терминала:

bash
source .venv/bin/activate

Признак успеха — в начале строки терминала появилась приставка (.venv):

(.venv) ivan@MacBook-Air analyst %

С этого момента python и pip в этом окне терминала относятся к окружению.

Команду нужно выполнять, находясь в папке проекта. Если терминал отвечает no such file or directory: .venv/bin/activate — ты в другой папке (проверь через pwd) или окружение ещё не создано.

Как проверить, что окружение активно

bash
which python

В ответе должен быть путь внутри твоего проекта, например /Users/ivan/projects/analyst/.venv/bin/python. Если команда отвечает python not found или показывает системный путь — окружение не активировано.

Установка библиотек в окружение

Активируй окружение и ставь как обычно:

bash
pip install numpy pandas matplotlib seaborn scipy statsmodels scikit-learn requests beautifulsoup4 jupyterlab

Это полный набор для книги. Всё установится внутрь .venv.

Выход, удаление, пересоздание

Выйти из окружения:

bash
deactivate

Удалить окружение — удалить папку .venv:

bash
rm -rf .venv

Осторожно с rm -rf: команда удаляет без корзины и без вопросов. Перед запуском убедись, что написал именно .venv и находишься в папке проекта. Твой код при удалении окружения не пострадает: он лежит рядом, а не внутри.

Если окружение сломалось (так бывает, например после обновления Python через Homebrew), его не чинят, а пересоздают: удаляют папку, создают заново и ставят библиотеки из requirements.txt. Это занимает пару минут.

Чего нельзя делать с окружением

  • Не клади свои файлы внутрь .venv. Эта папка служебная.
  • Не отправляй .venv на GitHub. Она большая и работает только на твоём компьютере. Добавь её в .gitignore (раздел 9).
  • Не переноси и не переименовывай папку проекта вместе с .venv. Внутри окружения записаны абсолютные пути; после переезда оно перестанет работать. Перенёс проект — пересоздай окружение.
  • Не копируй .venv другу. Передают requirements.txt, а окружение каждый создаёт у себя сам.
  • Не используй sudo pip install. Если хочется написать sudo — значит, окружение не активировано.

Другие инструменты

Ты встретишь упоминания других менеджеров окружений. Все они решают ту же задачу:

ИнструментЧто это
venvВстроен в Python. Достаточен для всей книги — используем его
conda (Anaconda, Miniconda)Отдельный менеджер, умеет ставить и разные версии самого Python. Популярен в науке о данных
uv, PoetryСовременные инструменты для управления проектом и зависимостями
pyenvПереключение между несколькими версиями Python на одном компьютере

Не распыляйся: начни с venv. Принцип у всех одинаковый, и перейти на другой инструмент потом будет легко.

6. requirements.txt: список библиотек проекта

Это текстовый файл, в котором перечислены библиотеки проекта. По нему проект разворачивается на любом компьютере.

Сохранить текущее состояние окружения:

bash
pip freeze > requirements.txt

В файле появятся строки с точными версиями:

numpy==2.1.3
pandas==2.2.3
matplotlib==3.9.2

Развернуть окружение по файлу (на другом компьютере или после пересоздания):

bash
pip install -r requirements.txt

pip freeze записывает вообще всё, включая десятки вспомогательных библиотек. Для учебных проектов допустимо написать файл руками и перечислить только то, что ты сам импортируешь:

pandas
matplotlib
seaborn
scipy
jupyterlab

Обновляй requirements.txt каждый раз, когда ставишь в проект новую библиотеку.

7. Jupyter

Запуск

Jupyter запускают из активированного окружения и из папки проекта:

bash
jupyter lab

В браузере откроется вкладка с файлами проекта. Терминал при этом занят — в нём работает сервер Jupyter, закрывать его нельзя. Чтобы остановить, нажми в терминале Ctrl+C и подтверди клавишей y. Для других команд открой новую вкладку терминала: Cmd+T.

Раз Jupyter установлен в окружение и запущен из него, ноутбуки видят все библиотеки этого окружения. Это самый простой и надёжный способ.

Проверка, что ноутбук использует нужное окружение

Выполни в ячейке:

python
import sys
print(sys.executable)

Путь должен вести в папку .venv твоего проекта.

Установка библиотеки из ноутбука

Если во время работы не хватило библиотеки, её можно поставить прямо из ячейки:

%pip install plotly

Команда %pip ставит библиотеку именно в то окружение, в котором работает ноутбук. После установки перезапусти ядро: меню Kernel → Restart Kernel.

Ядро (kernel)

Ядро — это процесс Python, который выполняет ячейки ноутбука. Что о нём нужно знать:

  • переменные живут, пока живо ядро; после перезапуска все ячейки нужно выполнить заново;
  • ячейки выполняются в том порядке, в каком ты их запускал, а не сверху вниз. Число в квадратных скобках слева от ячейки показывает порядок;
  • если ноутбук ведёт себя странно — Kernel → Restart Kernel and Run All Cells. Это же обязательная проверка перед публикацией.

8. VS Code

Visual Studio Code — бесплатный редактор кода. В нём удобно держать всё сразу: файлы проекта, ноутбуки, терминал и Git.

Установка — с сайта code.visualstudio.com (скачанное приложение перетащи в папку «Программы») или через Homebrew:

bash
brew install --cask visual-studio-code

Настройка:

  1. Открой папку проекта: File → Open Folder. Именно папку, а не отдельный файл.
  2. Во вкладке Extensions (значок с квадратами слева, Cmd+Shift+X) установи расширения Python и Jupyter от Microsoft.
  3. Выбери интерпретатор: Cmd+Shift+P → набери Python: Select Interpreter → выбери вариант с .venv.
  4. Открой встроенный терминал: Ctrl+` (именно Ctrl, клавиша слева от единицы). После выбора интерпретатора VS Code будет сам активировать окружение в новых терминалах.

Файлы .ipynb открываются прямо в VS Code. В правом верхнем углу ноутбука есть кнопка выбора ядра — там тоже нужно указать .venv.

Команда code в терминале

Удобно открывать проект в VS Code прямо из терминала. Один раз включи команду: Cmd+Shift+P → набери Shell Command: Install 'code' command in PATH. После этого в папке проекта достаточно написать:

bash
code .

9. Git и GitHub

Первая настройка

Git уже установлен вместе с Command Line Tools (раздел 2). Представься — один раз на компьютере; эти данные попадут в историю изменений:

bash
git config --global user.name "Твоё Имя"
bash
git config --global user.email "твоя_почта@example.com"

Почту укажи ту же, что в аккаунте GitHub.

Вход в GitHub

GitHub не принимает обычный пароль при отправке кода. Самый простой способ авторизоваться — официальная программа GitHub CLI:

bash
brew install gh
bash
gh auth login

Отвечай на вопросы: GitHub.com → HTTPS → Login with a web browser. Откроется браузер, где нужно подтвердить вход. После этого git push будет работать без запроса пароля.

Файл .gitignore

До первого коммита создай в корне проекта файл .gitignore:

bash
touch .gitignore

Открой его в VS Code и перечисли то, что Git не должен отслеживать:

# виртуальное окружение
.venv/

# секреты
.env

# служебные файлы Python и Jupyter
__pycache__/
.ipynb_checkpoints/

# большие и сырые данные
data/raw/

# служебные файлы macOS и редакторов
.DS_Store
.vscode/

.DS_Store — служебный файл, который Finder создаёт в каждой папке, куда ты заходил. В репозитории он не нужен. Чтобы не добавлять его в каждый проект, можно один раз настроить общий список исключений:

bash
echo ".DS_Store" >> ~/.gitignore_global
bash
git config --global core.excludesfile ~/.gitignore_global

Основные команды

КомандаЧто делает
git initСделать папку репозиторием
git statusЧто изменилось. Запускай постоянно
git add .Подготовить все изменения к сохранению

Первая отправка на GitHub

  1. На github.com нажми New repository, задай имя, не ставь галочки про README и .gitignore (они у тебя уже есть), нажми Create.
  2. В папке проекта выполни по очереди:
bash
git init
bash
git add .
bash
git commit -m "Первый коммит: структура проекта"
bash
git branch -M main
bash
git remote add origin https://github.com/ТВОЙ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
bash
git push -u origin main

Дальше рабочий цикл состоит из трёх команд: git add ., затем git commit -m "что сделал", затем git push.

Пиши сообщения коммитов по делу: «Добавил когортный анализ», а не «изменения» или «asdf».

Если после git commit без -m открылся странный текстовый редактор и непонятно, как выйти, — это Vim. Набери :q! и нажми Enter, затем повтори коммит с -m "сообщение".

10. Новый проект с нуля: пошагово

12. Файл .env и секреты

Не путай: .venv — это папка с окружением Python. .env — это текстовый файл с настройками и секретами проекта. Названия похожи, задачи разные.

Зачем нужен

Пароли от баз данных и ключи API нельзя писать прямо в коде: код попадает на GitHub, и секрет увидят все. Украденные ключи находят автоматические сканеры за считаные минуты.

Решение — хранить секреты в переменных окружения, а в коде только читать их.

Как пользоваться

Установи библиотеку:

bash
pip install python-dotenv

Создай в корне проекта файл .env:

bash
touch .env

Открой его в VS Code и запиши переменные:

DB_HOST=localhost
DB_USER=analyst
DB_PASSWORD=очень_секретный_пароль
API_KEY=abc123

Правила записи: одна переменная на строку, без пробелов вокруг =, без кавычек.

Прочитай значения в коде:

python
import os
from dotenv import load_dotenv

load_dotenv()                          # загрузить переменные из файла .env

password = os.getenv("DB_PASSWORD")
api_key = os.getenv("API_KEY")

Если ноутбук лежит в подпапке, load_dotenv() сам поищет файл в родительских папках.

Обязательные правила

  1. Добавь .env в .gitignore до первого коммита.
  2. Положи в репозиторий файл .env.example — такой же, но без настоящих значений. По нему другой человек поймёт, какие переменные нужны:
DB_HOST=
DB_USER=
DB_PASSWORD=
API_KEY=
  1. Если секрет всё-таки попал на GitHub — недостаточно удалить его следующим коммитом: он останется в истории. Ключ нужно немедленно отозвать и выпустить новый.

15. Если придётся работать на Windows

Книга написана под macOS, но на работе может оказаться Windows. Отличий немного:

macOSWindows (PowerShell)
Запуск Python вне окруженияpython3python
Активация окруженияsource .venv/bin/activate.venv\Scripts\Activate.ps1
Проверка путиwhich pythonwhere.exe python
Разделитель в путях/\
Палитра команд VS CodeCmd+Shift+PCtrl+Shift+P
Установка программHomebrewустановщики с сайтов или winget

При установке Python на Windows нужно поставить галочку Add python.exe to PATH. Если PowerShell не даёт активировать окружение, один раз выполни Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

Код на Python при этом одинаковый. Чтобы он работал на обеих системах, собирай пути через pathlib.Path (глава 2А) и всегда указывай encoding="utf-8" при работе с файлами.
