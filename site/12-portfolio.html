Глава 12. Проекты и портфолио

У начинающего аналитика нет опыта работы, поэтому работодатель судит по проектам. Три-четыре хороших проекта на GitHub значат больше любого сертификата: они показывают, что ты умеешь довести анализ от вопроса до вывода.

12.1. Что отличает хороший проект

Рекрутер тратит на портфолио пару минут, нанимающий аналитик — десять. За это время должно быть понятно:

  1. Какой был вопрос. Не «анализ датасета», а «почему клиенты не оформляют повторный заказ».
  2. Что ты сделал. Какие данные, какие методы.
  3. Что ты выяснил. Конкретные выводы с числами.
  4. Что рекомендуешь. Что бизнесу делать с этими выводами.

Признаки слабого проекта:

  • датасет «Титаник» или ирисы — их видели тысячи раз;
  • код без единого текстового пояснения;
  • графики без выводов;
  • нет ответа на вопрос «и что?»;
  • полная копия чужого решения.

12.2. Как работать с чужими проектами

Репозитории из этого раздела — образцы, а не источник для копирования. Копия не научит тебя ничему и легко вскрывается на собеседовании первым же вопросом «а почему вы здесь сделали так?».

Порядок работы:

  1. Прочитай проект целиком. Запиши: какой вопрос, какие шаги, какие выводы.
  2. Закрой его.
  3. Возьми тот же датасет или похожий и сделай свой анализ с нуля.
  4. Сравни с оригиналом. Что автор заметил, а ты нет? Где твоё решение лучше?
  5. Добавь своё: другой разрез, дополнительную гипотезу, дашборд.

12.3. Разбор репозиториев-образцов

На русском

Учебные проекты Яндекс Практикума и karpov.courses. Их ценность в том, что задачи приближены к реальным и сформулированы языком российского бизнеса.

DataAna1ytics/Projects_Data_Analytics Проекты курсов «Аналитик данных» и «Симулятор аналитика». Пример: проверка гипотезы о том, что спрос на авиабилеты растёт во время фестивалей, — данные собираются SQL-запросами, анализируются в pandas. Чему учиться: связка SQL → pandas → статистический тест в одном проекте.

Yourius/Projects_Ya Воронка событий и A/A/B-тест мобильного приложения, исследование рынка общепита Москвы, расчёт маркетинговых метрик. Чему учиться: как выглядит продуктовый анализ (глава 10) и корректно оформленный эксперимент (глава 9).

Lenupcik/portfolio Исследование аудитории киберспорта, дашборд в Yandex DataLens, запросы к демо-базе PostgreSQL «Авиаперевозки». Чему учиться: как оформить портфолио, в котором есть и код, и дашборд, и SQL.

На английском

GonorAndres/data-analyst-path Шесть законченных проектов: анализ рынка Airbnb, когортный анализ e-commerce, A/B-тест, KPI-отчёт и другие — с ноутбуками и дашбордами. Чему учиться: это самый сильный образец в списке. Обрати внимание на структуру репозитория и на то, как каждый проект закрывает отдельный навык.

AsifRashid01/DataAnalyst_PortfolioProjects Исследование данных в SQL, визуализация в Tableau, очистка данных в SQL, анализ корреляций в pandas. Чему учиться: классический стартовый набор из четырёх проектов, который можно повторить шаг за шагом.

noztas/DataAnalystProjects Очистка и разведочный анализ данных об увольнениях в MySQL (CTE, оконные функции), дашборд в Excel, проекты на pandas. Чему учиться: как показать уверенный SQL на реальной задаче очистки.

12.4. Четыре проекта для твоего портфолио

Вместе они закрывают всё, что спрашивают у junior-аналитика. Датасеты ищи в awesome-public-datasets — выбирай тему, которая тебе самому интересна: с ней ты не бросишь на полпути и сможешь увлечённо рассказывать на собеседовании.

Проект 1. SQL-исследование

  • Навыки: JOIN, агрегация, CTE, оконные функции (глава 3).
  • Данные: Chinook для разминки, затем более крупная база — например, демо-база «Авиаперевозки».
  • Вопросы: кто самые ценные клиенты? Как меняется выручка по месяцам? Какие товары покупают вместе? Как распределены клиенты по странам и сегментам?
  • Результат: файл .sql с пронумерованными и прокомментированными запросами плюс README с 5–7 выводами.

Проект 2. Разведочный анализ на Python

  • Навыки: очистка, pandas, визуализация, описательная статистика (главы 5–8).
  • Данные: «грязный» датасет из реальной жизни: недвижимость, вакансии, такси, общепит.
  • Вопросы: от чего зависит цена? Какие сегменты выделяются? Какие аномалии есть в данных?
  • Результат: ноутбук по плану EDA из раздела 8.7 с выводами после каждого блока и итоговыми рекомендациями.

Проект 3. Продуктовая аналитика и A/B-тест

  • Навыки: метрики, воронка, когорты, проверка гипотез (главы 9 и 10).
  • Данные: лог событий интернет-магазина или приложения, данные A/B-теста.
  • Вопросы: где теряются пользователи? Как меняется удержание от когорты к когорте? Победил ли вариант B?
  • Результат: ноутбук с воронкой, тепловой картой удержания, расчётом теста и решением: внедрять или нет.

Проект 4. Дашборд

  • Навыки: BI-инструмент, выбор метрик, дизайн (глава 7).
  • Данные: можно взять данные проекта 2 или 3.
  • Результат: публичная ссылка на дашборд в DataLens или Tableau Public и README с описанием: для кого он, на какие вопросы отвечает.

Пятым, необязательным, может стать проект с моделью (глава 11): прогноз оттока или сегментация клиентов.

12.5. Структура проекта

project-name/
├── README.md            — описание проекта
├── data/                — данные или ссылка на них
├── notebooks/
│   └── analysis.ipynb   — основной ноутбук
├── sql/                 — запросы, если есть
├── images/              — ключевые графики для README
└── requirements.txt     — список библиотек

Файл requirements.txt получается командой:

bash
pip freeze > requirements.txt

Большие файлы данных и любые ключи доступа в репозиторий не кладут. Создай файл .gitignore и перечисли в нём то, что Git должен пропускать: папку .venv, папку data/raw, файл .env.

12.6. README проекта

README — это то, что человек увидит первым и, возможно, единственным. Шаблон:

# Название: вопрос, на который отвечает проект

## Задача
Два-три предложения: кто заказчик, что он хочет узнать, какое решение от этого зависит.

## Данные
Откуда, за какой период, сколько строк, что означает одна строка.

## Что сделано
- Очистка: удалено N дубликатов, обработаны пропуски в ...
- Анализ: ...
- Проверка гипотез: ...

## Главные выводы
1. Вывод с числом.
2. Вывод с числом.
3. Вывод с числом.

(один-два ключевых графика)

## Рекомендации
Что стоит сделать бизнесу.

## Инструменты
Python (pandas, seaborn, scipy), SQL, DataLens.

## Как запустить
Команды для установки и запуска.

Выводы должны стоять в README, а не только в конце ноутбука: до конца ноутбука дочитают немногие.

12.7. Оформление ноутбука

  • Начало: заголовок, задача, описание данных, оглавление.
  • Импорты — в первой ячейке, все вместе.
  • Перед каждым блоком кода — текстовая ячейка: что и зачем сейчас делаем.
  • После каждого графика и таблицы — вывод в одном-двух предложениях.
  • Конец: общие выводы и рекомендации.
  • Перед публикацией выполни Restart Kernel and Run All — ноутбук должен отработать сверху вниз без ошибок.
  • Убери черновики, отладочные ячейки и огромные выводы таблиц.

Проверка: дай ноутбук человеку не из аналитики. Если по тексту и графикам он понял, что ты выяснил, — проект готов.

12.8. Профиль на GitHub

  • Закрепи (pin) 3–4 лучших проекта на главной странице профиля.
  • Сделай README профиля: кто ты, что умеешь, ссылки на проекты и контакты. Для этого создаётся репозиторий с именем, совпадающим с твоим логином.
  • Давай репозиториям понятные имена и описания: moscow-restaurants-analysis, а не project1.
  • Учебные упражнения (решения numpy-100, pandas_exercises) держи в отдельном репозитории и не закрепляй: они показывают регулярность, но проектами не являются.

Задания

  1. Разбери два репозитория из раздела 12.3 по схеме из раздела 12.2 и запиши для каждого: вопрос, шаги, выводы, что бы ты сделал иначе.
  2. Сделай проект 1 (SQL) и выложи на GitHub.
  3. Доведи EDA из задания главы 8 до уровня проекта 2: добавь README и рекомендации.
  4. Сделай проект 3 и проект 4.
  5. Оформи профиль GitHub и закрепи проекты.
  6. Попроси кого-нибудь из сообщества аналитиков посмотреть портфолио и дать обратную связь.

Проверь себя

  • Какие четыре вещи должны быть понятны из проекта за пару минут?
  • Почему нельзя копировать чужой проект?
  • Что должно быть в README?
  • Зачем перед публикацией запускать ноутбук целиком с нуля?
